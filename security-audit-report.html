OAuth 2.1 / OIDC Protocol Compliance

9 findings
High

Refresh token expiration is never validated

src/Outback/Rinsen.Outback/Grants/RefreshTokenGrantTypeHandler.cs · GetRefreshTokenGrantAsync (61–76)  ·  src/OutbackApp/Rinsen.IdentityProvider/Outback/GrantAccessor.cs · GetRefreshTokenGrantAsync (87–113)

Why: Refresh token grants are created with an Expires value (RefreshTokenGrantTypeHandler.cs:85), but neither the grant handler nor the storage layer ever checks it against the current time. An expired refresh token remains a valid bearer credential indefinitely. Violates RFC 6749 §6 and RFC 9700 §4.12 (the token endpoint MUST validate token lifetimes).

Remediation
private async Task<RefreshTokenGrant> GetRefreshTokenGrantAsync(string refreshToken, string clientId)
{
    var refreshTokenGrant = await _grantAccessor.GetRefreshTokenGrantAsync(refreshToken);

    if (refreshTokenGrant == default)
    {
        throw new SecurityException("No RefreshToken found");
    }

    if (refreshTokenGrant.Expires < DateTimeOffset.UtcNow)
    {
        throw new SecurityException("Refresh token has expired");
    }

    if (!string.Equals(refreshTokenGrant.ClientId, clientId, StringComparison.Ordinal))
    {
        throw new SecurityException("RefreshToken is not valid for client");
    }

    return refreshTokenGrant;
}

Medium

No refresh-token reuse detection / token-family revocation

src/Outback/Rinsen.Outback/Grants/RefreshTokenGrantTypeHandler.cs · GetTokenAsync (40–59)  ·  src/OutbackApp/Rinsen.IdentityProvider/Outback/GrantAccessor.cs:87–113

Why: Rotation exists (a new token is issued per refresh, old token marked Resolved at GrantAccessor.cs:101), but replay of a consumed token merely fails with invalid_grant while the current family token stays valid. RFC 9700 §10.5 requires that reuse of a rotated refresh token triggers revocation of the entire token family (theft detection).

Remediation
var existing = await _outbackDbContext.RefreshTokenGrants
    .Include(m => m.Client)
    .SingleOrDefaultAsync(m => m.RefreshToken == refreshToken);

if (existing == null)
{
    throw new Exception("Refresh token not found");
}

if (existing.Resolved is not null)
{
    // Reuse detected: revoke the entire token family
    var family = await _outbackDbContext.RefreshTokenGrants
        .Where(m => m.FamilyId == existing.FamilyId).ToListAsync();
    _outbackDbContext.RefreshTokenGrants.RemoveRange(family);
    await _outbackDbContext.SaveChangesAsync();
    throw new SecurityException("Refresh token reuse detected; family revoked");
}

src/Outback/Rinsen.Outback/Controllers/OAuthController.cs:268–269 (VerificationUri), :352–355 (GetIssuer)  ·  WellKnownController.cs:49–52

Why: The scheme is forced to https regardless of the actual request scheme. In any non-TLS deployment (dev, internal HTTP) the advertised issuer no longer matches the actual origin, breaking issuer validation on the RP side and producing an unreachable verification_uri.

Non-constant-time comparisons of secrets (4 sites)

ClientService.cs:47 (client secret)  ·  AuthorizationCodeGrantTypeHandler.cs:138 (PKCE challenge)  ·  LocalAccountService.cs:131 (password hash)  ·  IdentityController.cs:248 (invite code)

Why: Ordinal == / != / SequenceEqual short-circuit on the first differing byte, leaking a timing side-channel that can be exploited over the network to recover secrets byte-by-byte. .NET provides CryptographicOperations.FixedTimeEquals exactly for this.

Remediation (representative — apply the same pattern to all four sites)
using System.Security.Cryptography;

var secretHashBytes = Convert.FromBase64String(WebEncoders.Base64UrlDecode(secretHash));
var match = client.Secrets.Any(s =>
{
    var stored = Convert.FromBase64String(WebEncoders.Base64UrlDecode(s));
    return stored.Length == secretHashBytes.Length
        && CryptographicOperations.FixedTimeEquals(stored, secretHashBytes);
});
if (!CryptographicOperations.FixedTimeEquals(
    Encoding.UTF8.GetBytes(codeChallenge),
    Encoding.UTF8.GetBytes(codeGrant.CodeChallenge)))
{
    throw new SecurityException("Code verifier is not matching code challenge");
}
Medium

Client secrets stored as unsalted SHA-256

src/Outback/Rinsen.Outback/Helpers/HashHelper.cs:9–14  ·  used by DefaultInstaller.cs:107 and sample/SampleServer/InMemoryAccessors/ClientAccessor.cs:25,49

Why: Unsalted single-round SHA-256 offers no per-secret salt and is GPU/rainbow-table precomputable. A leaked Secrets table yields all client secrets. Client secrets should be stored with a KDF (PBKDF2/Argon2id) with a per-client salt, or as full-length random values compared at runtime.

Remediation
public static (string Hash, string Salt) GetClientSecretHash(string secret)
{
    var salt = RandomNumberGenerator.GetBytes(16);
    var hash = Rfc2898DeriveBytes.Pbkdf2(
        Encoding.UTF8.GetBytes(secret), salt, 600_000, HashAlgorithmName.SHA256, 32);
    return (WebEncoders.Base64UrlEncode(hash), WebEncoders.Base64UrlEncode(salt));
}
Medium

PBKDF2 iteration count (100,000) below OWASP minimum

src/OutbackApp/Rinsen.IdentityProvider/IdentityOptions.cs:7

Why: OWASP Password Storage Cheat Sheet recommends ≥ 600,000 iterations for PBKDF2-HMAC-SHA256. 100,000 is ~6× weaker against offline brute force once the database is compromised.

Remediation
public IdentityOptions()
{
    IterationCount = 600_000;
    NumberOfBytesInPasswordHash = 128 / 8;
    NumberOfBytesInPasswordSalt = 128 / 8;
}

Per-account IterationCount is persisted, so existing users keep working; new accounts get the stronger default.

Admin endpoint dumps the full application configuration

AdminController.cs:31–41 (GetConfiguration → ((IConfigurationRoot)_configuration).GetDebugView())

Why: Exposes every configuration value — including the SQL connection string with its embedded password and any secret supplied via environment variables — to every admin principal, in a form trivially scrapeable from the admin UI.

Remediation
public IActionResult GetConfiguration()
{
    var sensitive = new[] { "connectionstring", "password", "secret", "invitationcode" };
    var result = ((IConfigurationRoot)_configuration).AsEnumerable()
        .Where(kvp => sensitive.All(s => !kvp.Key.Contains(s, StringComparison.OrdinalIgnoreCase)))
        .ToDictionary(kvp => kvp.Key, kvp => kvp.Value);

    return Ok(result);
}
